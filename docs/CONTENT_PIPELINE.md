# Content pipeline

## Current starting point

Research and source-book analysis for Core Drawing are complete enough to support the current architecture. The single proposed course sequence is [`../curriculum/CORE_DRAWING_MAP.md`](../curriculum/CORE_DRAWING_MAP.md). Its companion [`CORE_DRAWING_REDESIGN.md`](../curriculum/CORE_DRAWING_REDESIGN.md) records synthesis and audits; [`CORE_DRAWING_VISUAL_MANIFEST.md`](../curriculum/CORE_DRAWING_VISUAL_MANIFEST.md) records instructional assets and prompts. Superseded plans are in `curriculum/archive/` and are historical only.

**Do not author any lesson in the proposed sequence or generate planned images until the learner approves the map and production specification.** Existing enriched pilot JSON/assets remain unchanged as prototype/reference material and retain legacy IDs. The current map is planning data, not lesson prose or application content.

## After approval

1. Recheck only the relevant source pages/sections and record precise locators, insight and any scan limitations.
2. Draft bounded lesson batches from the approved map and current lesson schema. Preserve the short core explanation, substantive optional Read More teaching, and separate Sources & Further Reading record.
3. Create or select only the visual assets specified by the approved manifest. Use original instructional sketches or deterministic diagrams as specified; record provenance and alt text.
4. Review lesson objectives, dependencies, varied subjects, tool readiness, timing, life/reference accessibility, source accuracy, visual alignment and concept recurrence.
5. Correct accepted findings and update the canonical map only when an architecture decision changes.
6. Run the configured checks when implementation/content production is authorized. Inspect deployment output to confirm private material is excluded.

## Roles and evidence

Use Sol for orchestration, curriculum decisions, source synthesis and senior review; use Luna workers for bounded book checks, lesson drafting, visuals, metadata and routine QA when available. Give each worker only the project context needed. Use page-referenced evidence and target follow-up checks rather than moving full books into synthesis context.

## Privacy

Original books, raw extracts/OCR, source images, analyses, research, personal notes and scratch work stay under `sources/`. They must remain private and excluded from GitHub Pages. Do not reproduce book illustrations or source prose. Record provenance and distribution decisions for every deployed asset.
