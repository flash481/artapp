The final 150-lesson Core Drawing architecture is in [`../curriculum/CORE_DRAWING_MAP.md`](../curriculum/CORE_DRAWING_MAP.md). The broad architecture is approved and the final Landscape & Nature expansion has passed sequence, whole-course coverage, landscape false-coverage, and specialist-creep review. [`CORE_DRAWING_REDESIGN.md`](../curriculum/CORE_DRAWING_REDESIGN.md) records the synthesis and audits; [`CORE_DRAWING_VISUAL_MANIFEST.md`](../curriculum/CORE_DRAWING_VISUAL_MANIFEST.md) records planned instructional assets and prompts. The prior 130-lesson map and older plans are historical only.

**Do not author lessons or generate planned images until the learner approves the production specification and reference/provenance plan.** The architecture is content-complete, but this pass produced planning and audit documents only. Existing enriched pilot JSON/assets remain unchanged prototype/reference material with historic IDs. The map is not lesson prose or application content.

## After production approval

1. Confirm the first bounded lesson-authoring batch, recheck its relevant source pages/sections, and record precise locators, insight and any scan limitations.
2. Draft lesson batches from the approved map and current lesson schema. Preserve the concise core explanation, substantive optional Read More teaching, and separate Sources & Further Reading record.
3. Create/select only assets specified by the approved manifest. Use original instructional sketches or deterministic diagrams as specified; record provenance and alt text. Use ArtApp-owned fixed-view fallback references for every outdoor lesson.
4. Review objectives, dependencies, varied subjects, tool readiness, timing, life/reference access, source accuracy, visual alignment and concept recurrence.
5. Correct accepted production findings. Change the canonical map only if a material architecture decision emerges; do not add specialist topics by default.
6. Run configured checks when implementation/content production is authorized. Inspect deployment output to confirm private material is excluded.

## Roles and evidence

Use Sol for orchestration, curriculum decisions, source synthesis and senior review; use Luna workers for bounded book checks, lesson drafting, visuals, metadata and routine QA when available. Give each worker only the project context needed. Use page-referenced evidence and targeted source checks rather than moving full books into synthesis context.

## Privacy

Original books, raw extracts/OCR, source images, analyses, private research, personal notes and scratch work stay under `sources/`. They must remain private and excluded from GitHub Pages. Do not reproduce book illustrations or source prose. Record provenance and distribution decisions for every deployed asset.
